# Nova Travel

Сайт туристического проекта на Flask, HTML, CSS и чистом JavaScript.

## Состав проекта

- `app.py` — Flask-приложение, каталог туров, проверка и приём заявок.
- `templates/index.html` — страница сайта и форма бронирования.
- `static/css/style.css` — стили и адаптивная вёрстка.
- `static/js/script.js` — каталог, форма, меню, галерея и слайдер отзывов.
- `static/img/` — локальные изображения.
- `nova_travel.sqlite3` — база заявок, создаётся автоматически при первом запуске.

## Локальный запуск (Windows PowerShell)

```powershell
cd "путь\к\папке\nova_travel"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python app.py
```

Откройте `http://127.0.0.1:5000/`.

Почтовые переменные задаются в том же окне PowerShell перед запуском:

```powershell
$env:MAIL_USERNAME="nova_travel_ru@mail.ru"
$env:MAIL_PASSWORD="ПАРОЛЬ_ВНЕШНЕГО_ПРИЛОЖЕНИЯ"
$env:BOOKING_RECEIVER="miniker99@gmail.com"
python app.py
```

Для Mail.ru нужен отдельный пароль внешнего приложения. Не публикуйте его в GitHub и не отправляйте в чат. Если почта временно недоступна, заявка всё равно сохраняется в SQLite; статус отправки письма фиксируется в базе и отображается в журнале приложения.

## Публикация на Render

- Root Directory: `nova_travel` (если репозиторий содержит проект во вложенной папке; иначе оставьте поле пустым).
- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn app:app`
- Environment: `MAIL_USERNAME`, `MAIL_PASSWORD`, `BOOKING_RECEIVER`.

**Важно о хранении заявок:** SQLite-файл на обычной файловой системе Render может исчезнуть при пересоздании экземпляра или новом deploy. Для постоянного хранения подключите Persistent Disk и задайте `DATABASE_PATH` на путь внутри диска (например `/var/data/nova_travel.sqlite3`). Для нескольких экземпляров приложения лучше перейти на управляемую PostgreSQL.

## Проверка

- `GET /` — главная страница.
- `GET /api/tours` — JSON-каталог.
- `POST /book` — приём заявки; обязательные поля проверяются на сервере.

Пример JSON для `POST /book`:

```json
{
  "name": "Иван",
  "phone": "+7 988 650-99-00",
  "tour_id": "sulak",
  "date": "2027-06-15",
  "people": "2",
  "promo": "",
  "comment": ""
}
```

## Что проверить перед реальным запуском

1. Указать подтверждённые телефон, адрес, график работы и почту компании.
2. Проверить фактическую достоверность рекламных заявлений (стаж, число клиентов, автопарк, круглосуточная поддержка и т. п.). Не оставляйте цифры и обещания, которые компания не может подтвердить.
3. Заменить демонстрационные отзывы на реальные отзывы с разрешением авторов либо убрать их.
4. Подготовить и разместить полноценную политику обработки персональных данных и согласовать юридический текст формы с требованиями применимого законодательства. Сейчас форма содержит чекбокс согласия, но отдельная юридическая политика в проект не включена.
5. Проверить все цены, состав туров, даты и условия отмены с владельцем бизнеса.
6. Протестировать SMTP с действующими учётными данными и проверить, что письмо приходит на адрес получателя.
7. Настроить резервное копирование базы заявок.

В репозитории нет секретов и паролей. Файл `.env` не добавляйте в Git.
